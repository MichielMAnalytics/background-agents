The OpenInspect MCP server lets an MCP client such as Claude Code read your sessions and automation runs, and optionally start and steer sessions, create and run automations, or import skills, without opening the web UI. Your control plane serves it at `/mcp`, and a client authenticates with a [personal access token](/integrations/personal-access-tokens).

## Set it up

1. Create a token under **Settings › Access tokens**. For investigation, select **Read-only**. Add write permissions only if you want the assistant to make changes; see the table below.
2. Register the server with your client, using your control plane's URL:

   ```bash
   claude mcp add --transport http open-inspect https://<your-control-plane>/mcp \
     --header "Authorization: Bearer oi_pat_..."
   ```

   Administrators find the exact URL under **Settings › API policy**. A client that only runs local servers can reach it through a bridge such as `mcp-remote` with the same header.

The server is stateless: each request stands alone, so a client checks on a session by calling `get_session` again rather than waiting for a notification. An administrator can turn MCP off under **Settings › API policy**; tokens then keep working with the API directly.

### Local server (deprecated)

The repository also contains a local stdio server with the same tools, in `packages/mcp-server`. It will be removed once the hosted server covers everything it does; prefer the hosted URL above. To run it, build it from a checkout and register it:

```bash
npm run build -w @open-inspect/shared
npm run build -w @open-inspect/mcp-server
claude mcp add open-inspect \
  --env OPEN_INSPECT_CONTROL_PLANE_URL=https://<your-control-plane> \
  --env OPEN_INSPECT_TOKEN=oi_pat_... \
  -- node /absolute/path/to/packages/mcp-server/dist/index.js
```

Its control plane URL must use `https://`; plain `http://` is accepted only for a loopback address such as `localhost`.

## What it can do

| Tool                                                                                                                      | Needs the token to hold                                                                         |
| ------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `list_sessions`, `get_session`, `get_session_events`, `get_session_messages`, `get_session_diff`, `get_session_diff_file` | **Read sessions**                                                                               |
| `create_session`                                                                                                          | **Create sessions**, **Read sessions**, **Collaborate in sessions**, and use of its target      |
| `send_prompt`                                                                                                             | **Read sessions** and **Collaborate in sessions**                                               |
| `list_automations`, `list_automation_invocations`, `get_automation_run`                                                   | **Read automations**                                                                            |
| `list_skills`                                                                                                             | **Read skills**                                                                                 |
| `create_automation`                                                                                                       | **Create automations**, **Create sessions**, and use of its targets                             |
| `trigger_automation`                                                                                                      | **Run your automations** or **Run any automation**, **Create sessions**, and use of its targets |
| `import_skill_from_git`, `update_skill_from_git`                                                                          | **Manage skills** (administrators), which always comes with **Read skills**                     |

A token without a tool's permission gets an error, which usually names the missing permission or points to the tool's description, where the needed grant is stated. The token never exceeds your own role or your workspace's [API policy](/administration/personal-access-tokens), and nothing it does can stop, archive, or delete a session, open a session's sandbox editor, terminal, or tunnels, delete or pause an automation, delete a skill, or reach secrets or workspace settings. A run started with `trigger_automation` uses only what the token was granted, even where your role allows more.

## Keep the assistant in check

Session transcripts and diffs are content the agent and your repositories produced, and they go straight into the assistant's context. Treat them as untrusted. Text in a session can try to persuade the assistant to call a write tool, and that call would act with your authority:

- A session started or prompted this way runs its instructions in a sandbox, as you, straight away. The agent there can run any command the sandbox allows, with that session's secrets and repository access, and can push branches and open pull requests. Withholding the sandbox URLs from a token does not limit this.
- An automation runs its instructions later, in a sandbox, as you.
- A skill assigned globally loads into every later session in the workspace.

A read-only token cannot be talked into writing: the control plane refuses the call whatever the assistant sends. The token's grant is the only limit anything enforces.

The server marks its write tools as not read-only, and many MCP clients ask before running such a tool by default. That marking is a hint, though, and whether you are asked depends on your client's settings: a client set to approve tools automatically runs writes without asking. If you give a token write permissions, check how your client handles write tools, and read what a write is about to create before you approve it.
